# GAMTU Edge 프롬프트 발전 흐름

## 1. 기존 안심OS 피치 점검

기존 제품:

> 독거노인 가정의 여러 센서 신호를 개인 생활패턴과 함께 분석해, 돌봄사가 먼저 확인할 위험을 골라주는 시스템

발표 후 피드백:

* 마지막 `감사합니다 / Q&A` 누락
* 제품을 한 문장으로 설명하기 어려움
* SWOT·SCAMPER가 형식적임
* 가격과 구매 이유가 불명확함
* 기존 공공 돌봄서비스와 차별성이 약함

도출된 문제:

> 사회문제 해결 아이디어는 있지만, 고객이 왜 돈을 내야 하는지는 충분히 설명되지 않았다.

## 2. 스타트업 관점에서 재평가

심사자가 볼 요소를 중심으로 재검토:

* 정확한 고객과 구매자
* 현재 사용 중인 대안
* 경쟁제품보다 나은 이유
* 가격 및 총소유비용
* 초기 진입시장
* 복제하기 어려운 기술·데이터
* 작게 시작할 수 있는 MVP

초기 피벗 제안:

> 독거노인용 통합 OS보다, 카메라를 설치하기 어려운 욕실의 이상 체류를 감지하는 저가형 IoT 안전키트

하지만 팀 논의에서는 개별 안전제품보다 기존 안심OS의 **로컬 허브 계층**에 집중하는 방향을 선택했다.

## 3. 안심OS의 2단계인 로컬 허브로 제품 축소

초기 로컬 허브 정의:

> 서로 다른 안전센서를 연결하고, 인터넷이 끊겨도 현장에서 위험을 판단·확인·전달하는 돌봄 전용 엣지 허브

핵심 기능:

* 이기종 센서 연결
* 로컬 사건 판단
* 현장 사용자 확인
* 오프라인 안전기능
* 센서·통신 장애 감지
* 중앙 서버와의 동기화

한계:

* 일반 IoT 게이트웨이 및 Home Assistant와 차별화가 어려움
* 돌봄시장만으로는 범용성이 제한됨
* 제조사 API와 센서 규격에 의존함

## 4. 범용 AI 엣지 서버로 확장

팀에서 합의한 새로운 방향:

* 제품은 로컬 AI 엣지 허브에 집중
* 가정·병원·공장 등 모든 IoT 사이트에 적용
* 서로 다른 센서 출력값을 현장 맥락과 함께 해석
* 중앙 AI 서버에서 모델을 학습
* 경량화된 추론 모델을 각 로컬 허브에 배포
* 인터넷 단절 중에도 로컬 추론 지속
* 정전 시 자체 배터리로 24~48시간 비상운영
* Safety Policy와 현장 사용자 최종 제어권 유지

초기 제품 정의:

> 이기종 IoT 환경을 위한 장애 내성형 로컬 AI 판단 서버

## 5. 기술적 과대주장 정리

초기 아이디어:

> 모든 센서가 어떤 형식의 값을 보내도 AI가 자동으로 이해한다.

수정된 개념:

> 장치·위치·단위·정상범위·주변 센서와의 관계를 이용해 데이터 의미를 추정하고 공통 사건으로 변환한다.

초기 아이디어:

> 초전도체 기술로 정전 중에도 상태를 유지한다.

수정된 개념:

* 내장 배터리
* 저전력 비상모드
* 상태 체크포인트
* 이벤트 로컬 저장
* Watchdog
* A/B 이미지
* 자동 Rollback
* 전력 복구 후 동기화

핵심 원칙:

> 실패하지 않는다고 주장하는 대신, 장애를 감지하고 핵심 기능을 유지한 뒤 안전하게 복구한다.

사용자가 설정한 제품 가정:

* 적용시장별 개발이 이미 완료됨
* 하드웨어와 소프트웨어 모두 완성
* 합리적인 가격으로 판매 가능

제품 정의:

영문:

> Connect anything. Understand locally. Operate continuously.

## 7. GAMTU Open Protocol 확정

자체 프로토콜:

# GAMTU Open Protocol — G-OP

G-OP의 역할:

> 서로 다른 센서의 원시 데이터를 공통된 현장 의미와 사건으로 변환하는 시맨틱 프로토콜

변환 구조:

```text
DEVICE
→ PLACE
→ CONTEXT
→ EVENT
```

예시:

```text
82 + 0 + CLOSED
→ 욕실 장기 체류 가능성
```

```text
76.4 + 7.8 + RUN
→ 모터 베어링 이상 가능성
```

## 10. 첫 디자인 결과의 문제

생성된 슬라이드의 장점:

* 네이비 기반의 일관된 테크 스타일
* 선명한 대형 제목
* 시안·오렌지 포인트
* 제품 하드웨어의 일관된 형태

문제:

* 텍스트 카드 비중이 높음
* 화면이 발표자의 설명을 반복함
* 핵심 구조를 보여주는 일러스트레이션 부족
* 연결선이 장식적으로 사용됨
* 공간 평면도 안에 빈 영역이 많음
* 시연 장면에서 센서→허브→사용자 흐름이 불명확함

새 디자인 원칙:

> 발표자가 설명하고, 슬라이드는 시스템의 관계와 작동 장면을 보여준다.

## 11. 손그림 기반 시각 구조 정의

사용자가 제시한 핵심 스케치:

* 중앙 또는 현장에 GAMTU Edge
* 주변에 적용 사이트
* 현장 센서와 사용자
* 위에는 중앙 학습 서버
* 센서 데이터는 로컬 Edge로 이동
* 중앙 서버는 모델을 학습해 Edge로 배포

이를 바탕으로 시각 중심 프롬프트를 작성:

* 화면의 65~75%를 다이어그램에 사용
* 완전한 설명문 최소화
* 센서·장치·연결·사건을 그림으로 표현
* 가정·병원·공장은 컷어웨이 또는 시스템 도면형 일러스트로 구성
* 슬라이드마다 핵심 비주얼 하나

## 12. 생성된 일러스트의 구조적 오류 발견

Genspark 결과에서 발견된 핵심 오류:

### 잘못된 구조

```text
HOME ─┐
HOSPITAL ─→ 하나의 GAMTU Edge
FACTORY ─┘
```

이 구조는 하나의 물리적 허브가 모든 사이트를 연결하는 것처럼 보였다.

### 정확한 구조

```text
가정 센서 → 가정 GAMTU Edge
병원 센서 → 병원 GAMTU Edge
공장 센서 → 공장 GAMTU Edge
```

그리고:

```text
각 GAMTU Edge
↕
중앙 AI 학습 서버
```

중앙 서버 역할:

* 여러 사이트의 학습용 데이터 수집
* 대규모 모델 학습
* 분야별 모델 경량화
* 검증된 엣지 모델 배포

각 GAMTU Edge 역할:

* 현장 데이터 수집
* G-OP 변환
* 로컬 추론
* 현장 알림·제어
* 장애 중 독립 운영

## 13. 슬라이드별 수정사항

### 1장

* HOME·HOSPITAL·FACTORY 연결 제거
* GAMTU Edge 제품만 표시하거나 일러스트 제거
* 제품명에 집중

### 2장

* 중앙 물음표 제거
* 원시 데이터가 장치·위치·단위와 분리된 상태를 일러스트로 표현

### 3장

* 사이트마다 개별 GAMTU Edge 배치
* 사이트 간 연결 제거
* 상단에 중앙 AI 학습 서버 배치
* 데이터는 위로, 검증된 모델은 아래로 이동

### 4장

* 중앙 GAMTU Edge를 가장 크게
* 좌측 원시 데이터와 우측 사건 결과를 더 작게
* G-OP 변환을 화면 중심으로 설정

### 5장 — 가정

```text
거실·욕실·침실 센서
→ 가정 GAMTU Edge
→ 보호자 휴대폰
↔ 중앙 AI 서버
```

### 6장 — 병원

```text
병상·병실·복도·화장실 센서
→ 병동 GAMTU Edge
→ 간호사 대시보드
↔ 중앙 AI 서버
```

### 7장 — 공장

```text
진동·온도·전류·PLC
→ 공장 GAMTU Edge
→ 운영자 대시보드
↔ 중앙 AI 서버
```

### 8장 — 범용성

* 하나의 물리적 Edge가 모든 사이트를 연결하는 표현 금지
* 같은 코어 아키텍처가 각 사이트에 독립적으로 배포되는 모습
* 공통 파이프라인:

```text
SENSE → G-OP → CONTEXT → DECIDE → ACT
```

### 9장 — 독립성

* GAMTU Edge를 가장 크게 배치
* 인터넷과 전력망은 끊어진 점선으로 표현
* 하단에 장애 상태 전이 표시:

```text
장애 감지
→ 비상모드
→ 핵심 기능 유지
→ 복구 감지
→ 동기화
→ 정상모드
```

### 10장 — 제품과 가격

* Mini·Pro·Critical 동일한 시각적 중요도
* Critical 하이라이트 제거
* 일반적인 플랜 카드 구조
* 경제적 가치 표시

### 11장 — 결론 및 Q&A

* 가격표와 분리
* GAMTU Edge 제품 하나만 크게 표시
* 세 핵심 메시지:

UNDERSTAND LOCALLY

## 14. 현재 최종 제품·발표 개념

### 제품

> 각 IoT 사이트에 독립적으로 설치되어 서로 다른 센서 데이터를 현장 맥락으로 해석하고, 외부 연결 장애에도 로컬 추론과 운영을 유지하는 AI 엣지 서버

### 시스템

```text
사이트별 센서
→ 사이트별 GAMTU Edge
→ 현장 사용자·제어

각 GAMTU Edge
↕ 학습 데이터·검증된 모델
중앙 AI 학습 서버
```

### 핵심 차별성

* G-OP 기반 이기종 데이터 의미 변환
* 현장별 독립 로컬 AI 추론
* 동일 코어의 여러 산업 배포
* 인터넷·전력 장애 중 핵심 기능 유지
* Safety Policy와 현장 사용자 최종 제어

### 최종 발표 문장

> GAMTU Edge는 특정 산업을 위한 센서 제품이 아닙니다. 동일한 코어가 각 IoT 사이트에 독립적인 로컬 AI 두뇌로 배포됩니다.
